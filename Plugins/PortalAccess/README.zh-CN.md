# PortalAccess（恢复功能暂停）

2026-10-05 进图发生访问冲突崩溃后，本版本暂停交互恢复。
F12 → 刷图与收益 → 传送门交互恢复，目前仅提供**只读诊断**。
旧配置中的 `RestoreInteraction: true` 会自动关闭，恢复开关不可开启；
插件不会获取游戏写入权限，停用或退出时也不进行还原写入。
底层写入接口仅允许离线测试操作测试程序自己的内存。

游戏转储记录了无效指针 `0x10100`，与原先两个单字节写入的组合一致，
当前客户端的只读分析已找到崩溃调用链中的 Targetable 析构函数，
确认其 0x50 处是动态数组；旧 0x51/0x52 偏移落在数组指针内部。
这些证据强烈指向布局错误，转储仍未包含实际被损坏的堆对象。
不得根据框架继承的旧偏移继续写入。

诊断从当前客户端的调试函数文字标签识别「可选中」「对玩家隐藏」「任务条件」
和「物品条件」四项状态。函数与标签必须位于游戏主模块内，字段不能重叠，
数值必须是布尔值，读取前后必须确认实体与组件身份一致。
不认识的结构不显示状态。此检查仅验证只读解释，不能证明门的模型或服务器进图次数已恢复；写入继续暂停。

活动、休眠实体和保留记录共用每次 15 毫秒、4,000 次读取上限；
每张实体表最多遍历 2,000 个节点，最多保留 128 个传送门身份。
切图或进程变化时停止采样。达到上限会标记采样不完整，大型地图可能漏读部分门。
配置和诊断在 `config/` 下，活动采样每 10 秒自动保存。

[离线测试](../../Tests/README.md) 仅使用模拟内存和测试进程自己的内存，不连接游戏。
